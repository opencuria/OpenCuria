# Native desktop clipboard

The embedded KasmVNC 1.3.3 viewer supports seamless **text/plain**, **text/html**, and **image/png** clipboard transfer with Chromium browsers (Chrome and Edge). The browser must grant clipboard permissions and the dashboard must be served in a secure context (HTTPS, or localhost for development). Clipboard transfer is active only while the connected desktop surface is visible and focused; switching tabs/windows, focusing dashboard inputs, hiding the surface, disconnecting, changing workspaces, or Computer-use disables it. A later genuine desktop click/paste reads the current local clipboard; VM contents are never replayed in the background. KasmVNC's built-in text clipboard panel remains the manual text-only fallback when seamless permissions or MIME support are unavailable.

When browser support or permission is unavailable, the viewer shows a short notice with a button that opens KasmVNC's native text-only clipboard panel on request. Images and HTML are not available through that fallback. A browser clipboard write already dispatched cannot be cancelled if focus changes while the browser handles it; all not-yet-dispatched writes and protocol uploads are fenced.

The backend patch is deliberately pinned to the deployed KasmVNC 1.3.3 `dist/main.bundle.js` SHA-256 and fails closed if that asset changes. Updating KasmVNC requires reviewing and updating the explicit patch anchors and regression tests. All direct Xvnc starts set `-DLP_ClipTypes text/plain,text/html,image/png`; already-running desktops need a restart before the server-side MIME list changes.

## Reproducible native transport + UI check

From the repository root, run `scripts/native-kasm-clipboard-e2e.sh`. Prerequisites: start the webapp Vite dev server (the E2E base URL defaults to `http://127.0.0.1:5173`; override with `E2E_BASE_URL`), install E2E dependencies with `cd e2e && npm ci`, and have the backend virtualenv at `backend/.venv`. The isolated fixture also needs KasmVNC 1.3.3 installed under `/usr/share/kasmvnc/www`, `Xvnc`, `xclip`, `xdotool`, `ffmpeg`, Python Tk (`python3-tk`), Node.js/npm, and Google Chrome. It starts a separate Xvnc display/ports, launches a native Tk text editor, applies the production Python proxy patch, and exercises real Chromium clipboard APIs, sends trusted Ctrl+V through the canvas into the native Tk text editor, and sends Ctrl+C to that native editor with `xdotool` before checking the VM X11 and browser clipboard contents. The script stops its child processes at exit but retains per-run logs and fixture files under `/workspace/.opencuria/playwright/native-vnc-<pid>/` for diagnosis. Screenshots are saved separately as `/workspace/.opencuria/playwright/native-kasm-clipboard.png` (transport lab) and `native-kasm-dashboard.png` (actual desktop UI). For setup context, see the [desktop clipboard section in the README](../README.md#desktop-clipboard).
